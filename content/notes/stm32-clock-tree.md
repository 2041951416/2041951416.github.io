刚上手时最容易犯的错误：外设配置全对，就是不通。回头一看，**时钟根本没开**，或者算错了总线频率，波特率差了整整一倍。

## 三条主线

STM32 的时钟树看着复杂，其实只有三条主线：

1. **时钟源** — HSI（内部 RC）、HSE（外部晶振）、LSI/LSE（低速，给 RTC 和看门狗用）
2. **PLL 倍频** — 把低频晶振变成高频系统时钟
3. **总线分频** — 把 SYSCLK 分给 AHB、APB1、APB2

以 F103 系列、8 MHz 外部晶振、目标 72 MHz 为例，标准步骤是：

```text
HSE ÷ M × N ÷ P  =  8 ÷ 1 × 9 ÷ 1  =  72 MHz
```

对应 CubeMX 里的参数：

| 参数 | 值 | 含义 |
|---|---|---|
| PLLM | 1 | HSE 先分频到 8 MHz（PLL 输入必须 1–2 MHz 附近才稳） |
| PLLN | 9 | 倍频到 72 MHz |
| PLLP | 1 | 再分频得到 SYSCLK |

注意不同系列公式不同。F4/F7 是 `HSE / M * N / P`，而 H7 还多一级，HSE 本身也要除以 2。**别背公式，看参考手册的时钟树图**，照着图上的除法器一级一级往下算。

## 总线频率决定外设时序

SYSCLK 分频后得到：

```c
// F103 @72MHz 的典型配置
// AHB  = SYSCLK / 1  = 72 MHz  → 内核、DMA、SRAM
// APB1 = SYSCLK / 2  = 36 MHz  → USART2/3、I2C、TIM2-7（定时器再 ×2 = 72MHz 计数）
// APB2 = SYSCLK / 1  = 72 MHz  → USART1、SPI1、GPIO、TIM1
```

这里有个特别容易踩的坑：**APB1 上的定时器，计数时钟是 APB1 × 2**。因为当 APB 预分频不为 1 时，定时器时钟会自动乘以 2。所以 TIM2 挂在 36 MHz 的 APB1 上，实际计数频率还是 72 MHz。

如果你按 36 MHz 去算 PWM 周期，输出频率会差一倍。

## 波特率算错多半是这里

USART 的波特率公式：

```c
// 以 USART1 挂在 APB2 = 72MHz 为例，目标 115200
// BRR = 72000000 / (16 * 115200) = 39.0625
// 整数部分 39 = 0x27，小数部分 0.0625 * 16 = 1 → 0x271
USART1->BRR = 0x271;
```

代码里我一般直接写成可读的形式，让编译器去算：

```c
#define APB2_CLK   72000000UL
#define BAUD       115200UL
USART1->BRR = (APB2_CLK + BAUD / 2) / BAUD;
```

`+ BAUD/2` 是为了四舍五入，少这一项在高速波特率下误差会累积。

## 一个检查习惯

配置完任何外设，先做这一步：

```c
// 关闭状态下也要能读到时钟使能位
assert(RCC->APB2ENR & RCC_APB2ENR_USART1EN);
assert(RCC->CFGR & RCC_CFGR_SWS_HSE);   // 确认真的切到了 HSE
```

`RCC->CFGR` 的低两位是**当前实际使用的时钟源**，不是你想用的那个（那在 `SW` 位）。`SWS` 读出来是 HSI，说明 PLL 或 HSE 启动失败，芯片自动回退到了内部 RC——这时候所有时序都是错的，但程序看起来"能跑"。

## 记住这张图

- 时钟没开 → 外设寄存器写不进去，读回全是 0
- 总线频率算错 → 串口乱码、定时器不准、I²C 时序失败
- 程序进了 `HardFault` → 先查是不是在关闭外设时钟的情况下访问了它

这三条覆盖了我遇到的大部分"玄学"问题。
